DevSecOps CI/CD pipeline

A Jenkins pipeline that takes a Spring Boot app from a Git commit to Kubernetes, with code analysis, a quality gate, container image scanning and Vault-managed secrets along the way. I built it as my project for the C-DAC PG Diploma in IT Infrastructure, Systems and Security (PG-DITISS).

What happens on every run

Each stage runs in order. If one fails, the pipeline stops there and Slack gets the result.

  1. 1

    Checkout with Git

    Jenkins pulls the latest code from GitHub.

  2. 2

    Build and unit test with Maven and JUnit

    Compiles the app, runs the unit tests and publishes the test results in Jenkins.

  3. 3

    Code analysis with SonarQube

    Static analysis for bugs, code smells and security issues. Results are stored in SonarQube backed by PostgreSQL.

  4. 4

    Quality gate in SonarQube

    SonarQube sends its verdict back to Jenkins through a webhook.

    The pipeline stops here if the code fails the gate.
  5. 5

    Docker build

    A multi-stage build produces a small image that runs the app as a non-root user.

  6. 6

    Image scan with Trivy

    Scans the image for known vulnerabilities (CVEs) and writes an HTML report.

  7. 7

    Store the scan report in AWS S3

    The Trivy report is uploaded to an S3 bucket so it can be reviewed later.

  8. 8

    Push the image to Docker Hub

    The image is tagged with the build number and pushed.

    Docker Hub credentials come from HashiCorp Vault at runtime, never from the Jenkinsfile.
  9. 9

    Deploy to Kubernetes

    Rolls out the new image as a Deployment, exposed through a NodePort Service.

  10. Notify in Slack

    After every run, success or failure, Jenkins posts the job name, build number and a link to the build.

What I would improve next

Reviewing my own pipeline as a security reviewer would, these are the changes I would make before using it in production.

  • Fail on serious vulnerabilities. Trivy only reports today. Adding --exit-code 1 --severity HIGH,CRITICAL would turn the scan into a second gate.
  • Secure the Vault connection. Run Vault over TLS with certificate verification switched on.
  • Replace the deprecated deploy plugin with kubectl, Helm or a GitOps tool such as Argo CD.
  • Scan earlier. Add secret scanning with Gitleaks and dependency scanning with OWASP Dependency-Check.
  • Harden the deployment with resource limits, a restrictive securityContext and a read-only root filesystem.
  • Sign the images with cosign and deploy by digest instead of the latest tag.
